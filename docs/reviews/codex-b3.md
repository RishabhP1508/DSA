Source conventions were reconciled instead of copied blindly:

- CP-Algorithms uses a sentinel/half-open boundary formulation; exact ordinary/rotated search here uses inclusive lo..hi and bounds uses half-open [lo,hi).
- Original matrix problem uses strict row boundaries; nondecreasing row-major order also suffices, and this app permits equality across row boundaries.
- Original shipping problem restricts days<=n; the app's positive-input extension permits days>n, returning the heaviest package.
- Runestone uses a max-placement selection variant and first-position quicksort pivot; the app places minima and uses a middle-position pivot with separate lists.
- Runestone warns that slices must be removed to guarantee merge-sort's O(n log n) time. Open Data Structures' recurrence and CPython's linear slice implementation support the correct per-level derivation: linear slices at each of logarithmically many levels retain O(n log n) time. Slices do destroy an O(log n) recursive binary-search bound when an O(n)-length slice is made, which is a different recurrence.
- VisuAlgo's merge animation was inspected live in Exploration Mode, including depth/partitions and the temporary destination. Its in-place copy-back convention differs from this app's returned Python lists. Its quicksort uses in-place partitions, so its space claims are not inherited by the app's three-list code.
- McGill's expected bucket-sort theorem uses independent uniform occupancy and a bucket count proportional to n; its quadratic inner-sort analysis differs from this app's Python sorted. The app states the needed occupancy assumption and does not infer it from a fixed k=5 or from one sample.
- Closed intervals merge when endpoints touch; positive-duration meeting scheduling treats touching endpoints as compatible. These conventions solve different objectives and are stated explicitly.
